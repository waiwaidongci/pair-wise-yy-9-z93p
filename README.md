# 古法蓝晒底片整理室 · 母液开封与分装放行台

运行：

```bash
npm start
```

访问 `http://localhost:3040`。页面分两个页签：「底片整理」（既有功能）与「母液开封与分装放行台」。
数据保存在 `data/cyanotype-negative-room.json`，首次启动会为放行台补入一个种子批次（B-0620）。

## 放行台业务规则

- 同一药液批次至多存在一张未结束分装单（待放行 / 待复核）。
- 登记分装单时校验：批次存在、当班交接已确认、无未结束单、分装量为正且不超过母液余量。
  任一冲突返回 409，**在写存档之前判定，不产生半截记录**。
- 单内登记分装量（ml）、显影浓度（%）与操作者。浓度合格区间 18–22：
  - 合格 → 待放行，分配一个显影槽；
  - 越界 → 只转待复核，**不占显影槽**。
- 复核必须由登记操作者之外的**另一人连续两次取样**，两次取样均落合格区间且原批次仍在效期才放行；
  待复核单放行时才补占显影槽，槽全满时返回 `no_free_tank` 冲突。
- 更正母液余量、效期、交接状态，或更正单内浓度，都会让相关已放行单**失效重算**
  （回待放行或待复核，越界同步让出显影槽，须重新双人取样）。
- 所有变更只追加事件，**旧稿只读**；队列、批次余量、槽位占用均由事件履历折叠得到，刷新/重启后一致。

## 三个业务文件

| 文件 | 职责 |
| --- | --- |
| `station/intake.js` | 入口层：入参校验、用例编排、冲突错误码；判定不通过绝不写存档 |
| `station/decision.js` | 判定层：纯业务规则（浓度区间、登记前置、双人复核、效期、失效重算） |
| `station/archive.js` | 存档层：只追加事件履历 + 批次/队列/显影槽读模型折叠 |

`server.js` 只负责 HTTP 路由，把 `/api/station/*` 绑定到入口层。

## API

- `GET  /api/station/state` 批次、分装队列、显影槽、批次履历
- `POST /api/station/batches` 母液开封
- `POST /api/station/batches/correct` 更正余量 / 效期 / 交接状态（放行失效重算）
- `POST /api/station/orders` 分装登记（冲突 409，不产生半截记录）
- `POST /api/station/orders/:id/review` 复核取样（连续两次由同一他人取样）
- `POST /api/station/orders/:id/correct` 更正浓度（放行失效重算）
